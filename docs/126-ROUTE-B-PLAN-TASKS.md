**THE UNIT NEVER CHANGES.** `g_ClockTimer` stays an integer count of 60ths.
**All 152 references and every "N sixtieths" duration constant keep working.**
The seven `for (i = 0; i < g_ClockTimer; i++)` sub-step loops run 0 or 1 times
instead of always 1 — **correct behaviour, not a regression.** `99` §4's headline
cost (hundreds of duration constants) **evaporates** — `117` §4.2, `118` §3.

exist in the tree. The engine already expects frames where nothing ticks.

remainder (`lvupdate240rem`) and expose a float timestep (`lvupdate60f`) while
keeping integer 60ths for legacy constants. **They never did a migration — their
engine was always like that — so there is a validated DESIGN and no patch to
lift.** MIT, may influence anywhere.
