The mission and its constraints

00-STATE §1–2

Four things are not negotiable, and nine performance and embodiment constraints bind every plan. A plan that does not satisfy them is considered unfinished, not merely imperfect.

[MEASURED]
A number came out of an instrument or the source. Can be built on.
[REPORTED]
The wearer saw it. Outranks a log when the two disagree.
[INFERRED]
Reasoning only. Explicitly may not be built on.
[ASSUMED]
Carried over from an earlier era and not re-checked.
RULE 1
Every git commit is the owner's. Never stage, branch, merge or tag.
RULE 2
Delete nothing. Every knob stays reachable; superseded work is marked, never removed.
RULE 3
Fix it in the source — anything may change, provided the game stays true to its spirit.
RULE 4
P1–P9 constrain every plan.
P1 · sim rate
60.0f / actualHz, never a literal, always pinnable.
P2 · projection
Four tangents per eye per frame. Never a stored FOV angle.
P3 · resolution
One runtime variable. No second, window-derived notion of view width.
P4 · cost
Pay structural cost once, never per frame.
P5 · evidence
No performance claim without an instrument that can fail.
P6 · pose
The sim owns the pose. The renderer only consumes it.
P7 · body
Two hands and the body are one articulated system.
P8 · aim
Independent of facing, camera and locomotion.
P9 · authority
The sim is authoritative for ballistics and position.

Two eras, one pivot

docs 01–226 · 227 · 227–292

The project has been built twice. Reading the archive without this distinction is the single easiest way to conclude that features already work which do not.

Era I — The recomp route

2026-08-21 → 2026-08-27 · docs 01–226 · ARCHIVED

VR built as RECOMP_PATCH mods on top of cblock85's statically recompiled GoldenEye. It got remarkably far: real stereo in the headset, 6DoF head tracking, a gun that followed the hand, a 90 Hz sim, a per-eye HUD and a virtual screen for the menus.

It was abandoned as the primary route, not because it failed, but because it could never be "from source." It stays on disk as a working reference and a fallback.

Era II — The native source port

2026-08-27 → present · docs 227–292 · LIVE

The 100% decomp plus SegfaultEvan/goldeneye-native's host layer: ordinary, editable C with no TLB gate and no recompiler. Everything the VR layer needs to reach — the camera, the aim path, the tick loop — is now a file you can open.

Six of the ten route stages are done. The engine itself is well understood; the VR layer is being rebuilt on top of it, in order, with a gate at every stage.

The pivot — doc 227, 2026-08-27

"I want to use the source code as the main source of me building this … so that when I release this it's actually special and not just another hack."

The obstacle that had routed the project to the recomp in the first place — that no native GoldenEye port existed — disappeared while the project was running. The decomp hit 100% and a complete native host layer shipped. The pivot was the re-check the original plan had explicitly asked for.

What carries over, and what does not

Carries over: every measurement, every design, every named trap, the whole Perfect Dark prior-art scan, and the entire 169 upgrade sheet. The recomp era is why the native VR layer can be built in the right order instead of discovered.

Does not carry over: the code. Stereo, 6DoF, hand aim, the HUD shift and the virtual screen exist in the recomp binary. In the native tree, none of them have been written yet. Any doc that says "BUILT AND WORN" before 227 means built and worn there.

Era I — the recomp build reference only

It became VR

  • Stereo fixed at the root. Two present draws were binding the same descriptor heap slot in one command list; D3D12 reads heaps at execution time. Real depth, images fuse, one gun. 69 70 71
  • 6DoF head tracking in the headset at 5838×4498 per eye, both eyes confirmed distinct by counter rather than by eye. 09 10
  • The gun follows your hand — position tracked and worn. 85
  • Per-eye HUD shift — the crosshair fuses. Took three attempts; GoldenEye's HUD sprites carry no matrix at all. 170 173
  • The flat game on a virtual screen in VR, built as a real 3D rectangle with genuine depth, so the headset never has to come off. 175

It became fast, and safe to close

  • 90 Hz sim — 59.3 → 87.1 fps, worn, "totally playable". The interpolator was deleted and stays deleted. 134 147
  • The exit no longer bugchecks the machine — B3/B4 closed, after five hard crashes traced to our own teardown, not the RAM. 75 181
  • MSAA forced off under VR rather than merely documented. 43

The aim problem, understood

  • The bullet leaves the barrel, not the eye — the muzzle node exists and the game already computes it. 164 212 213
  • The residual is camera-dependent and yaw-only, ±3° within a group — the signature of a camera term that should not be there. 223 226
  • Root cause named: the game camera never receives the head rotation. In the native port this is an ordinary editable line. 194 226
  • Perfect Dark's shipping VR port fully scanned — same engine, public source. Its designs seed U-02, U-08, U-09, U-25. 81 102 160 168

Rendering faults, diagnosed to a line

  • The widescreen hole's edge is a per-room portal scissor's lrx — matched to 0.00 native px, in two frames, two runs, two resolutions. 279
  • The room rectangle is fetched at six sites, not one; GETV_ROOMSCISSOR=0 removes most of the holes. 284 286 287
  • The vanishing props: three candidates eliminated by measurement — the 32000 radius, the prop cull box, and finally the room test itself. 288 289
  • The front-end text fault has one variable, ge_offset_x(), isolated by a proper 2×2 with the prediction written first. 287
  • The 90 Hz "black triangles" were never triangles — a divider that turned itself on above 60 Hz. Out of stereo's path. 268

Method, which is why the rest holds

  • 00-STATE.md as the single entry point — session orientation cut from ~5,300 lines to ~170, deleting nothing.
  • Evidence tiers on every claim, and a standing retractions section. Four of one session's own predictions were recorded as measured false.
  • Run sheets with every outcome written before the run, so a result cannot be read backwards into a conclusion.
  • Rule 17 — any tool that falls back to "the newest" instead of failing is a silent-staleness bug and gets a gate. Five surfaced in one session; every one had reported success. 271
  • The masked-zero rule — a zero downstream of a test that rejects most of its input is not an exoneration. 289

The stereo divergence

Stage 6 · blocks the gate

The two eyes admit different geometry

first job

One frame, zero separation, byte-identical projection matrices: eye 0 draws 1060 triangle commands and 1940 vertices; eye 1 draws 622 and 1355. The cameras are identical, the scissors are correct halves, the pools do not overflow. The only thing that differs is the viewport rectangle, and something in room admission or portal traversal is reading it. Find out what.

EVIDENCE [MEASURED] · 292 §5a · everything else in the session is downstream of this

Who owns model->render_pos per eye

design decision, unmade

A model reaching the alpha pass in one eye without the opaque pass that rebuilt its matrices saturates every matrix entry, because bondviewTransformManyPosToViewMatrix is an in-place f32→s32 fixed-point conversion, not a transform — so it is not idempotent. GETV_STEREO_MTXGUARD=2 suppresses the symptom and must not ship. It is a falsifier whose job is done. Fix the divergence first; the repair may not be needed at all.

The route's own assumption is retracted

retracted

258 nests the eye loop in lvlRender's body because split-screen already drives that body N times. That body does not survive being driven twice. Whether this is repairable inside the current shape, or whether the shape has to change, is the question session 293 should be able to answer — and must not assume either way.

The turn feels wrong, and it is the mouse

Stage 7

Five sessions of pacing instruments came back clean because the fault is not in them — vsync, the frame cap, sleep booking, presented-frame distribution and sim rate are all cleared. Re-diagnosed from wear: mouse-only, improves with frame rate, and it is the shape of the turn rather than judder. Four properties of the mouse path match all four reported facts — a per-frame accumulator with no timestep, a backlog cap expressed in frames, a 20% deadzone floor (so there is no small mouse turn), and a saturated count map. Which is exactly why it must be measured and not believed.

00-STATE §3 · MAIN-STATION-TASKS

Every commit, build and run belongs to the owner, on the main PC. These are the items the assistant cannot do and that block or endanger work already finished.

Blocking — delete the stale config line

A per-user config file still disables the slot fix, and it wins on the config search path. Every run block wipes the environment workaround first, so the fix from 262 is not in effect on this machine — it killed an arm mid-session. Until the line is gone, every run block must re-set the knob explicitly.

Session 290's three commits, in order

Decomp first — staged by explicit path list, never git add -A, because ~2,099 files sit CRLF-dirty in that worktree. Verify the staged diff reads 318 insertions across three files before committing. Then the harness, then the docs. The commit script will not do step 1 — that directory is invisible to all three of its passes.

Seven knobs are absent from the decomp's HEAD

They have been carried uncommitted for a dozen sessions. One of them prints the banner that is gate 4 of every run block on a knob this project calls blocking — on a fresh clone that gate reads as a clean pass. Another is the instrument behind the "combiner is exonerated" finding, which cannot be re-derived from a clone.

Regen before every native commit

Three renderer files are gitignored and reach git only through a generated patch. A native commit without a regen ships a tree a fresh clone cannot rebuild — that is how one instrument went missing for two days. The gate is verify reading 15/15, not a byte count, and it must run from Git Bash on the main PC.

Back up the EEPROM before every run

A snapshot script exists. There is an unresolved report of lost saves whose build and save path were never established.

Do not reopen

00-STATE §4–§6

Each of these cost at least a session. They are recorded here so the next one does not spend it again. Nothing is deleted — a dead theory stays readable, marked dead.

The room-visibility test is dead

The falsifier written for it fired: the knob took, and the props still vanished. Do not re-run that arm.

The 32000 radius and the prop cull box are dead

Both eliminated by measurement, not by argument — and one of them was eliminated a second time to check the accounting balanced.

vsync and the sim-rate term are cleared

Both were smoothness candidates; both measured clean, one marginally in the wrong direction. The complaint is the mouse.

Never set the player count to 2 for stereo

Stereo is two views, not two players. Both memory pools are sized by player count — the read that would have crashed the eye loop.

Never ship the matrix guard at mode 2

It is a falsifier that has done its job. Shipping it would make a design decision by accident.

A masked zero is not an exoneration

A counter reading zero downstream of a test that rejects 92.5% of its input proves nothing. Standing rule, learned the expensive way.

A grep is not a read

Five sessions in a row, a grep stood in for reading the code and produced a wrong site list. The rule now has its own name.

A source read may not cancel an arm

One did, and it cost five sessions on the wrong subsystem: the mouse and the pad share a sink, not a path.
