GEVR Beta vr438 (BYO-ROM, file-backed images)
==============================================

Thank you for trying GEVR. This cut is fan-honest about what is in the zip and what you must supply.

What you need
-------------
- A PC VR setup with OpenXR (SteamVR, Virtual Desktop OpenXR, PimaxXR, etc.).
- A **USA GoldenEye 007 .z64 ROM you legally own**. We do **not** ship Nintendo game data in this download.

What this zip contains
----------------------
- goldeneye.exe built with **file-backed images** (no ROM-derived combined.bin linked into the exe).
- Runtime DLLs (including glew32.dll, SDL2, OpenXR loader, MinGW runtimes).
- GevrRomStarter.exe and gevr_prepare.exe to pick your ROM and prepare the local image cache.
- Start-GEVR.bat (launches the ROM starter, not bare goldeneye.exe).

First run
---------
1. Unzip anywhere.
2. Always run **Start-GEVR.bat** (not goldeneye.exe alone).
3. When prompted, point at your **USA .z64**.
4. First prepare can take a bit while images land in:
   %LOCALAPPDATA%\GEVR\cache\<your-ROM-hash>\
5. Put the headset on. Recenter with **both thumbstick clicks**.

No ROM file is included in this archive. Later launches with this same zip and
the same ROM skip that wait.

Cache updates (vr438 and later tags)
------------------------------------
Each zip carries a **ship stamp** (this one is vr438). After you unzip a new
Beta and run Start-GEVR.bat, GEVR checks ship.txt in your cache folder. If that
stamp is missing or does not match, it rebuilds the cache once from your same
.z64. Expect **one** wait on that first launch - not every launch.

You do **not** need to delete the cache folder yourself when you update.

If pictures look wrong after an update, you can delete %LOCALAPPDATA%\GEVR and
run Start-GEVR.bat again with the same ROM. That is troubleshooting only.

Always use Start-GEVR.bat so the current tag and VR settings are applied.

Changes in vr438 (vs pulled vr434)
------------------------------------
- **Ship model fix:** vr434 accidentally shipped with ROM images embedded in goldeneye.exe. That release was **pulled**. vr438 requires your ROM and uses a file-backed image cache instead.
- Picture / boot settings from the chair (sharper VR, stereo view-restore via Start-GEVR.bat) still apply.

Known Beta quirks
-----------------
- Crashes still happen; please file Issues with headset + OpenXR runtime + whether you used Start-GEVR.bat + whether this was first launch after a new zip.
- Dam crate pop-in, murky Dam water, and one-eye glass bullet holes are still open.
- Multiplayer: local split-screen on a monitor still works; a **LAN / same-network multiplayer add-on** is on the roadmap later.
